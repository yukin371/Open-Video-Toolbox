# Desktop 工作台实施规划

## D1-0：边界与框架冻结

- 确认 Avalonia 版本、目标平台和发布方式。
- 建立 Desktop 的应用状态模型和 Core facade 边界。
- 固定首轮验收样例、日志字段和任务状态。

通过标准：Desktop 能启动、显示依赖状态和空任务列表，且不依赖 CLI 入口。

## D1-1：单任务工作流

- 导入一个视频。
- 展示 probe 结果。
- 选择预设和输出路径。
- 生成 `CommandPlan` / `edit.json`。
- preview、执行、展示日志和输出文件。

通过标准：能完成一次可重放的本地转码任务，失败时能看到 stderr 和结构化错误。

## D1-2：字幕与转写工作流

- 启动本地 `transcribe` 对应的 Core 服务。
- 导入/选择 SRT 或 VTT。
- 选择 sidecar 或 burn-in。
- 接入外部翻译产生的第二份字幕并合并。

通过标准：用户能完成“视频 -> 转写/字幕 -> 可选双语 -> 预览 -> 渲染”。

## D1-3：批量队列

- 多文件导入。
- 队列排序、暂停、取消和重试。
- 单项状态与总进度。
- 每项独立工作目录和产物路径。

通过标准：一批任务中单项失败不会吞掉其他任务日志，结果可定位到具体输入。

## D1-4：工作台收口

- 最近任务恢复。
- 预设导入/导出。
- 输出目录和日志快速访问。
- Windows 优先发布 smoke，随后评估其他平台。

通过标准：新用户无需手写 CLI 命令即可完成首轮闭环，维护者仍可从结构化产物复查全部步骤。

## 明确不进入 D1

- 完整时间线编辑器。
- 云端任务、账号和在线素材下载。
- 内置翻译/AI provider。
- 旧工具预设的逐项兼容。
