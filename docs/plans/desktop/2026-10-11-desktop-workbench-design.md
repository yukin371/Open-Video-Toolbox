# Desktop 工作台设计

## 1. 页面结构

首版采用单窗口、三栏工作区加底部日志结构：

- 顶部工具栏：添加媒体、添加目录、执行队列和清空队列等全局动作。
- 左栏：任务列表、任务数量、空状态和状态筛选入口。
- 中栏：当前任务工作区，按“视频压制 / 字幕 / 音频 / 计划”分 Tab，避免把所有能力堆在同一滚动表单中。
- 右栏：任务状态、进度和输出说明，使用主题化表面色保持低视觉压迫。
- 底部：独立的深色 stdout / stderr 日志面板，只让终端内容使用深色背景。

页面不使用复杂时间线。需要修改精确片段时，首版打开或导出 `edit.json`，由现有文本计划承接。

## 2. 任务状态

```text
Draft -> Validating -> Ready -> Queued -> Running
                                      |-> Succeeded
                                      |-> Failed -> RetryQueued
                                      |-> Cancelled
```

UI 只展示和触发状态转换；状态来源是 Core 的执行结果和取消信号。

## 3. 核心交互

### 新建任务

1. 选择文件或目录。
2. 自动 probe，并提示缺失的 ffmpeg/ffprobe/whisper 依赖。
3. 选择预设、输出目录和覆盖策略。
4. 选择字幕/转写/音频输入。
5. 生成计划并显示 preview。
6. 加入队列。

### 执行任务

- 任务行显示当前步骤、百分比、耗时和输出路径。
- 取消只发送给 Core 执行层，不强杀 UI 状态。
- 失败展开 stderr、命令计划和相关输入路径。
- 重试复用原计划，只有用户明确修改时才生成新变体。

### 视觉层级

- 工作台提供浅色 / 深色两套主题；浅色为默认，深色用于长时间夜间工作，日志面板在两种主题下都保持深色终端观感。
- 面板使用主题化的表面色与低对比度边框；具体色值集中在 `src/OpenVideoToolbox.Desktop/Themes/Light.axaml` 与 `Dark.axaml`，两套字典必须声明同一组 `App*` 键。
- 主操作使用强调色背景与强调色前景；普通操作使用表面色背景与正文色前景；危险操作使用危险色文字或描边。
- 不依赖 Avalonia 系统默认按钮前景色，避免深色背景上出现黑色文字。
- 界面不得在 `XAML` 中写死颜色字面量，必须引用主题资源键，否则切换主题时会出现局部不跟随的残留。
- 主题选择持久化到 `desktop-preferences.json`，并在窗口创建前应用，避免启动闪白。

> 变更说明（2026-10-11）：本节原有"固定浅色、深色只用于日志"的冻结条款已按原型探索结论解除。两套主题共用同一套 `App*` 资源键，切换由 `ThemeManager` 交换合并字典完成。

## 4. ViewModel 边界

- `WorkbenchViewModel`：窗口导航和当前工作区。
- `TaskQueueViewModel`：队列展示、排序、取消和重试命令。
- `TaskEditorViewModel`：预设、路径、字幕和音频选项。
- `ExecutionLogViewModel`：结构化状态与原始日志展示。

这些 ViewModel 不持有 FFmpeg 参数拼接规则、不解析字幕格式、不实现转写或渲染算法。

## 5. 可观察性

每个任务至少展示：输入路径、计划路径、预设、当前步骤、开始/结束时间、退出状态、stdout、stderr、输出产物和失败原因。日志应支持保存到任务工作目录，保证 GUI 关闭后仍可复查。
