# D1 Desktop 价值判断模板

最后更新：2026-04-26

## 目的

这份模板只服务一个判断：

> 在下一次 `E2-G1 / D1` 重判时，Desktop 是否已经比继续留在 `E2` 更值得做？

它不是 `D1` 实施计划，也不是需求池。它只要求判断者把“为什么现在值得做”写成可复核文本，而不是停留在感觉上。

## 使用时机

- `schema v1` 观察窗口已接近完成，准备执行下一次 `E2-G1 / D1` 重判时
- 或者 roadmap 需要重新比较 `Desktop` 与 `E2` 的优先级时

## 使用规则

1. 先填写事实输入，再写判断。
2. 先回答“为什么现在做”，再回答“做什么”。
3. 任何结论都必须能回指到现有文档、验证结果或明确的用户价值。
4. 只要 `Desktop` 的角色开始漂向新业务 owner，这份模板就应直接判为 `不通过`。

## 必过门槛

以下任一项为 `否`，本次价值判断直接结束，默认回落到“继续留在 `E2`”：

| 门槛 | 当前答案 | 证据 |
| --- | --- | --- |
| `schema v1` 观察窗口已满足 |  |  |
| Desktop 仍被限定为交互壳，而不是新业务 owner |  |  |

| 当前没有更高优先级的 `E2` 仓库内阻塞 |  |  |

## 判定标准

只有同时满足以下条件，才建议输出“启动 `D1`”：

1. 不做 Desktop 的真实代价已经具体、重复出现，而且无法再靠 CLI 文档或脚本低成本缓解。
2. 首轮 Desktop 能解决的是单一高频闭环，而不是“大而全 GUI”。
3. Desktop 不会引入新的业务 owner，也不会迫使 `Core` / `Cli` 边界回退。
4. 机会成本比较后，启动 `D1` 明显比继续做当前 `E2` 窄卡更值。

如果以上任一条件写不清，就默认维持：

```text
结论：继续留在 E2
```
