# Desktop 工作台启动评估

## 1. 当前事实

- Core 已覆盖媒体模型、预设、计划、命令构建、执行和日志。
- CLI 已覆盖探测、转码、模板、批量、字幕、转写、素材挂载、预览和渲染。
- `edit.json schema v1` 已有稳定窗口和快照护栏。
- Desktop 已采用 Avalonia 11.3.12，并完成单窗口三栏工作台、任务状态模型和本地队列持久化。
- 当前真正缺少的是字幕/转写到最终 render 的完整闭环，而不是新的媒体处理内核。

## 2. 价值判断

小丸工具箱式工作台的价值在于降低重复操作成本：用户不需要为每个文件手工拼参数，也不需要在多个命令之间切换来观察批量进度。这个价值与当前项目的 Core/CLI 能力直接匹配，且不会要求项目变成完整 NLE。

## 3. 架构风险

- UI 可能重新实现一套计划模型，导致 `edit.json` 与 GUI 状态分叉。
- 队列可能绕过 `Core.Execution`，造成日志、取消和错误语义不一致。
- “参考小丸”容易膨胀为全量复刻，带来大量预设和兼容负担。
- 为了翻译或在线能力引入 provider，会突破外部 AI 边界。

## 4. 启动判断

结论：**D1 已启动并进入 D1-2；继续按“小丸式本地工作台 MVP”推进，不扩展为完整视频编辑器。**

启动条件：

1. Avalonia 11.3.12 已锁定，发布策略继续 Windows 优先、保留跨平台路径。
2. 单任务闭环与批量队列已完成，字幕与本地转写正在接入同一执行链。
3. 首轮所有已落地业务动作均映射回现有 Core/CLI 契约。
4. D1-2 以阶段验收记录为准，不以“界面看起来完成”作为完成标准。

## 5. 暂缓条件

如果 Avalonia 依赖、跨平台发布或 Core 执行取消语义无法稳定落地，应先停在 Desktop shell，不继续扩页面；如果需求开始要求自由时间线、在线 AI 或云端任务，应另开产品边界评估。
